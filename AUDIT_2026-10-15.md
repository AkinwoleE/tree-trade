### Critical
**C-1 Gateway reserve drain with faucet tUSDC** (`usdc_gateway.move:72`). The collateral token is mintable for free (faucet) and by the admin, yet `unwrap` exchanges it 1:1 for real USDC that other users locked. PoC: `gateway_tests::poc_faucet_tusdc_drains_reserve`. *Recommendation:* before real value is involved, use a gateway-only collateral asset (no faucet, no admin mint) for the real-money deployment, or track per-user redeemable balances. Testnet-only today. **Status: needs decision.**

### High
- **H-1 Stale-price latency arbitrage.** Opens and closes use a price up to 60s old. At 1000x a 0.1% lag is worth about 76% of margin after the haircut (PoC `review_tests::stale_price_latency_arb`). *Recommendation:* a pull oracle (a signed Pyth/Decibel price newer than the tx, checked on-chain), or two-step execution (request, then fill at the next keeper price), or at minimum a staleness of a few seconds plus an open fee/spread. **Needs decision.**
- **H-2 Single-key oracle without on-chain bounds.** *Fixed partly:* the keeper now holds back any >2% move until a second tick confirms it. *Recommendation:* an on-chain max change per second, a multi-source median, and a dedicated keeper key. **Partly fixed / needs decision.**
- **H-3 Keeper runs with the admin/upgrade key on an always-on box.** *Recommendation:* create a dedicated keeper account (`oracle::add_keeper`, `exchange::set_market_keeper`, which exist today), and move admin/upgrade authority to a multisig or hardware key. **Needs decision.**
- **H-4 Keeper missed 1-click and queue-funded positions → never liquidated.** **Fixed** and deployed.
- **H-5 Keeper treated read failures as zero positions.** **Fixed.**
- **H-6 Hedger double hedge after a partial tick failure.** **Fixed**, with a regression test.

### Medium (selected; full list in REVIEW)
- Fixed: sponsor Sybil drain (M-1), limiter reset (M-2), IP spoofing (M-3), stale sequence-number cache (M-4), proxy path traversal using our API key (M-5, reproduced on prod), CCTP replay drain (M-7), fund-route race (M-11), unbounded impact params (M-14).
- Needs decision: hedge registry global-cap DoS (M-12); V3 caps default to unlimited when the keeper is down (M-13).
- Open: CCTP client polls forever (M-8), SSE fan-out (M-9), keeper key/sequence collisions (M-15), push loop shares a tick with liquidations (M-16), indexer-lag cursor (M-17), hedger lock/state/unknown-outcome robustness (M-18 to M-20).

### Low / Info
Fixed: queue head stuck behind an emptied entry, bust-buffer bound, tail bound (prover-checked), `remove_pool_seed` debt guard, session regex, CCTP length check, hedger consent and prune regex. Open: session key in plaintext localStorage for 7 days, float→u64 UI conversions, keeper hygiene. Info items are listed in REVIEW.

## 6. Economic attack analysis
- **Oracle/staleness at 1000x:** see H-1. This is the dominant economic risk; the haircut does not neutralise it.
- **Payout-queue griefing:** queue entries come only from real wins (min notional $1k), the crank is bounded, and payments are FIFO. Fees are waived while the queue is active (PT parity), and stakers lose fee income during long queues. Low.
- **SEEDS farming via self-trading / wash losses:** two accounts open opposite 1000x positions. The loser mints 100 SEEDS per $1 lost; the winner recovers about 86% after haircut and fee (1% move), so the net cost is roughly $0.14 per 100 SEEDS. SEEDS is non-transferable, but staked SEEDS earn USDC fees, so farmers dilute honest stakers. This matches Paper Trade's design. **Needs decision** (e.g. mint only on positions held ≥ N seconds, or vest/delay staking rewards).
- **OI-cap griefing:** caps trail at $1B headroom per side and the max position is $10M, so filling a side is impractical. If the keeper is down, caps stay at their last value (M-13). Low.
- **Liquidation front-running:** liquidation pays no reward, so there is no competition. The risk is the reverse: missed liquidations give traders a free option (H-4, fixed in the keeper; it still depends on keeper liveness → consider a liquidator incentive).
- **Instant staking:** stake → fee → unstake sniping is possible in principle (PT parity). Low.

## 7. Centralization & upgrade risks
- A single admin key controls package upgrades (compatible policy, so code can change arbitrarily within ABI compatibility), the oracle, pause, fee withdrawal and all risk/tokenomics parameters. It is currently also the keeper's hot key on the build box (H-3).
- `test_usdc` admin can mint unlimited collateral (fine for testnet; fatal with C-1 on value-bearing assets).
- Off-chain dependencies: one keeper process (prices, liquidations, caps), one hedger, Vercel in-memory rate limits.
- *Recommendations:* multisig (Aptos native multisig account) for admin/upgrade, a dedicated low-balance keeper key, a timelock on parameter changes, a published upgrade policy, and a third-party audit before mainnet.
